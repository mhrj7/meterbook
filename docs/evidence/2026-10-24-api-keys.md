## The key

`mb_live_` or `mb_test_` (the environment's kind), 40 random base62 characters (238 bits), then a 6-character base62
CRC-32 of the rest. Malformed keys and bad checksums are refused without a database lookup. Only the SHA-256 is
stored. The secret appears once, in the creation response, and is never written to the idempotency store: a repeat
of the same request is 409 `idempotency_key_used`.

| Property | How it is enforced | Test |
|---|---|---|
| One environment per key; a test key cannot reach live data | key bound to `(tenant, project, environment)` by a composite foreign key; the prefix names the kind | `a_key_says_where_it_belongs…`, `keys_of_another_environment_or_tenant_do_not_exist` |
| Scopes from a fixed vocabulary, never empty, no duplicates | validation → 422 `scope_unknown`, `scopes_duplicated` | `validates_requests` |
| A key cannot manage keys, users or tenants | `/v1/api-key` has its own security chain; everywhere else a key is just an invalid bearer token → 401 | `a_key_cannot_call_anything_but_api_key`, e2e |
| Revocation is immediate | each verification reads the database; a revoked key is 401 on the next request | `a_revoked_key_is_rejected_on_the_very_next_request`, e2e |
| Callers cache at most 30 s and never cache a refusal | 200 carries `Cache-Control: max-age=30, private`; 401 carries `no-store` | API test; EKS check |
| Rotation without downtime | successor with the same name and scopes; the old key expires after the grace period (default 24 h, max 7 days, 0 = at once), or at its own earlier expiry; a key rotates once | `rotation_keeps_the_old_key_working…`, `rotation_keeps_an_earlier_expiry…` |
| Expiry | optional `expires_at`, in the future and at most 2 years ahead; expired keys are 401 | `a_key_stops_working_when_it_expires` |
| At most 50 live keys per environment | the environment row is locked while counting, so concurrent creates cannot overshoot; expired keys do not count | `an_environment_has_at_most_50_live_keys…` |
| Tenant isolation | forced row-level security on `api_keys`; looking up a presented key is the one platform-scoped read | RLS guard test, `keys_of_another_environment_or_tenant_do_not_exist` |

## End to end (CI, real Keycloak and PostgreSQL)

The tenant admin signs in through Keycloak, creates a project, and creates a `usage:write` key in its production
environment. Then:

| Step | Result |
|---|---|
| `GET /v1/api-key` with the key | 200: tenant Acme, kind `live` |
| The same key on `GET /v1/projects` | 401: a key is not a person |
| Admin revokes the key, then `GET /v1/api-key` | **401 on the next request** (asserted to be under 60 s) |

## What the tests found, and the fixes

| Found by | Problem | Fix |
|---|---|---|
| API test for rotation expiry | Timestamps were serialized in the JVM's zone (`+05:30` on a laptop), against `api-standards.md`. Pods run in UTC, which hid it in CI and on EKS | `spring.jackson.time-zone: UTC` for every endpoint; a test asserts UTC (#37) |
| API test with a signed-in person's authentication on `/v1/api-key` | 500: the controller expected a key | The chain requires the `API_KEY` authority and answers anything else with 401 (#37) |
| Design review of the limit | Expired keys would count toward the 50-key limit forever, and a rotation at the limit would be refused | Only live keys count; rotation may exceed the limit briefly (#36, #37) |
| jOOQ code generation | The self-referencing `rotated_to` key generated clashing navigation methods, with a warning on every build | Implicit join paths turned off; queries name their joins (#37) |
